# 期现跟踪模拟交易所（my-go-exchange × ctp-crawler）

> 状态：aligned  
> 更新：2026-02-14  
> 来源：`/to-project` 对齐结果

## 1. 一句话定位

对 **策略/研究开发者** 在 **验证中国期货交易思路** 场景下的 **缺乏可跑的带真实行情模拟环境** 问题，本项目提供 **Go 实现的、价格跟踪真实合约的本地模拟交易所（撮合 + 结算 + 移仓）**，以达到 **从外部 tick 到一笔模拟成交、持仓与资金可查询可回放** 的可观察结果。

## 2. 问题与背景

- 现状与痛点：
  - `ctp-crawler`：已有期货 tick 采集 / 1 分钟 K 线 / 展示链路，但 **没有撮合、账户、结算**。
  - `my-go-exchange`：已有 orderbook + matching（Limit/Market，GTC/IOC/FOK）+ 部分账户骨架，但标的是 crypto、无真实行情、API/Web 为空、无期货结算。
  - 两边未打通：不能在「真实合约价格轨迹」上做模拟开平仓与结算研究。
- 为什么现在做：
  - 用户明确要融合两边，打造 **带实时行情的模拟交易所**；且定调 **全部用 Go**，后续把 `ctp-crawler` 能力重写进 `my-go-exchange`。
- 问题陈述（可反驳）：
  - 「本地撮合引擎 + 外部真实 tick 做市」能否在体验上等价于行情软件的模拟交易，并支撑策略沙箱所需的保证金、盯市与移仓账务？

## 3. 用户与场景

| 角色 | 描述 | 关键场景 |
|------|------|----------|
| 主用户 | 策略/研究开发者（本人，单用户） | 订阅 cu/al/rb/if 等主力合约；子账户下多空单；日终盯市；到期前移仓；复盘成交与持仓 |
| 次要干系人 | 未来的扩展阅读者 / 可选协作者 | 只读看盘；不承诺多用户平台 |

## 4. 成功标准

可观察、可检查：

1. **端到端一笔模拟成交**：外部 tick 进入 → 报价 bot 在盘口双边挂单 → 用户 WS 下单 → 本地成交回报 → 子账户持仓/资金变化 → web 与 WS 均可见。
2. **价格跟踪可测**：同合约的 mark/盘口中心随 HTTP 快照 tick 更新，与源价偏差与时延有日志或指标可查。
3. **账务闭环**：日终盯市写入结算记录；移仓生成成对换月单并产生持仓迁移；规则表可改乘数/保证金率并影响计算。
4. **回归可跑**：orderbook/matching 既有测试保持通过；新增 fill/bot/结算单测覆盖关键规则。

## 5. 范围

### In scope

- 中国期货 **3–5 个主力合约**（建议 `cu` / `al` / `rb` / `if` 近月，以配置为准）。
- 外部行情 V1：**HTTP 快照轮询**（akshare 同源思路）→ Kafka `tick`。
- 本地 **orderbook 撮合**（保留 my-go-exchange 核心）+ **贴外部盘口双边报价 bot**。
- 期货账务：合约乘数、保证金（可配规则表）、多空持仓、浮动/实现盈亏。
- **每日盯市结算** + **换月成对单移仓**。
- **类 CTP 语义的 WS 交易协议**（简化子集：报单/撤单/查询/回报）。
- 三服务：`md-ingest` / `exchange` / `web`；Kafka + Postgres。
- web：看盘（K 线/盘口/tick）+ 下单面板 + 持仓/结算页。
- 单用户 + **子账户**（API token 即可用，无注册登录）。

### Out of scope

- 真实资金、出入金、KYC、多租户计费。
- 完整 CTP 字段集 / 真柜台协议兼容承诺。
- 交割月特殊规则（梯度保证金临交割、限仓、配对交割、自动强平临期合约）。
- 全量 137+ 合约、夜盘日历精细化、交易所规则自动同步服务。
- 加密货币标的；`ctp-crawler` 的 Java/Python 栈与 AI review 流水线不迁入。
- 多 bot 自循环造深度、撮合延迟竞赛、生产级 HA。

## 6. 核心概念与术语

| 术语 | 含义 | 避免混用的词 |
|------|------|----------------|
| 外部行情 / tick | 真实市场快照（HTTP 轮询所得），只读参考 | 「本所盘口」「成交回报」 |
| 本所盘口 | 本地 orderbook 双边 level，由 bot+用户单构成 | 「实时行情」（易与外部 tick 混） |
| mark 价 | 由外部 tick 导出的标记价（默认最新价/盘口中间价） | 「结算价」「成交价」 |
| 报价 bot | 贴外部买卖价双边挂单的做市对手方，受库存约束 | 「策略用户」「真实对手方」 |
| 模拟成交 | 本所撮合产生的 Trade，不进入真实市场 | 「真实成交」 |
| 盯市结算 | 用结算价重估持仓并入账的无负债日终动作 | 「移仓」「强平」 |
| 换月成对单 | 移仓=旧月平仓单 + 新月开仓单各一笔（可同价/限价） | 「直接改持仓」 |
| 子账户 | 单用户下的资金/持仓隔离单元 | 「用户」「账户所有人」 |
| 规则表 | 合约乘数、保证金率、涨跌停、最后交易日/移仓窗口配置 | 「硬编码参数」 |
| 类 CTP WS | 消息名与字段语义向柜台靠拢的简化 JSON/WS 协议 | 「完整 CTP API」 |

## 7. 模块 / 能力划分

```
[md-ingest] --tick--> [Kafka] --tick--> [exchange: md-sub + bot + matching + account/settle]
                                           |                      ^
                                           | book/trade/pos        | orders
                                           v                      |
                                         [web] <------ WS 交易/行情 ------> [策略/客户端]
```

| 模块 | 职责 | 不负责 |
|------|------|--------|
| md-ingest | HTTP 拉外部快照；规范化 tick；发 Kafka | 撮合、账户、历史 K 线长期仓 |
| exchange | 类 CT PWS 接入；bot 报价；orderbook 撮合；保证金/持仓/盯市/移仓；规则表 | 页面渲染、外部 HTTP 爬取 |
| web | 看盘 + 下单 + 持仓/结算展示；代理 WS 或直连 exchange | 撮合与账务计算 |
| marketdata 核心类型 | Instrument / Tick / Level / Trade 等共享模型 | 持久化细节 |
| rule-config | 合约与保证金等规则的加载/热更新入口 | 交易所规则爬取 |
| （保留）matching/orderbook | 价格优先、时间优先、TIF 语义 | 期货账务 |

## 8. 技术选型与约束

| 项 | 结论 | 理由 / 决策点 |
|----|------|----------------|
| 运行环境 | Docker Compose 可编排；本地 dev 可多进程 | 对齐 md/exchange/web + Kafka + Postgres |
| 语言/框架 | **Go 1.26** 重写全部；宿主 `my-go-exchange` | 用户定调「全部使用 go，ctp-crawler 后续重写进来」 |
| 撮合 | 保留 `internal/orderbook` + `internal/matching`，驱动方式改为 tick→bot→book | 用户选「保留 orderbook+行情 bot」 |
| 数据/存储 | **Postgres**（gorm 已在 go.mod）；Kafka 传 tick/事件流 | 用户选「Go 多服务+保留 Kafka」 |
| 行情源 V1 | HTTP 快照轮询（非 CTP DLL） | 用户选 HTTP 轮询；实时性=秒级快照 |
| 交易协议 | **类 CTP 语义 WS**（简化子集） | 用户点名 WS 交易协议且偏柜台语义 |
| 外部依赖 | Kafka、Postgres；HTTP 行情源 | 不引入 Java/Python 业务服务 |

硬约束：

- 宿主仓库：`E:\Projects\my-go-exchange`；本文档位于 `docs/project/PROJECT.md`。
- 不做真钱与合规；不承诺完整 CTP 字段兼容。
- 首期合约数量 3–5 个主力，可配置。

软约束（假设）：

- 结算价 V1 = **当日收盘/最后 tick 价**（后续可改为均价）。
- mark 价 = 外部最新价（或盘口中价，实现时二选一并写进指标）。
- 单用户 + 子账户；鉴权 = 静态 token。
- `ctp-crawler` 作为需求/合约清单/字段语义的 **输入参考**，不在其上继续演进。
- bot 无做市盈利目标，只保证双边可成交与库存有界。

## 10. 风险与验证

| 风险 | 影响 | 验证方式 |
|------|------|----------|
| 「模拟交易软件体验」与「本地 orderbook」不一致（价差/成交概率与真市偏离） | 策略结论不可信 | 记录 mark vs 本所 mid 偏差；bot 参数可配；文档写明非真实成交分布 |
| HTTP 快照延迟/缺档导致 bot 挂出坏价 | 荒谬成交或拒单风暴 | tick 年龄阈值停报；涨跌停过滤；坏 tick 拒绝 |
| 结算/移仓规则算错 | 资金与持仓错误 | 规则表表驱动单测；日终对账（持仓×乘数×结算价） |
| 交割月被排除后仍上近月临近到期合约 | 模拟失真 | 移仓窗口配置 + 到期前强制提醒/只减仓开关 |
| Kafka 引入复杂度拖慢 M1 | 长期无端到端 | M0 先跑通最小 tick 管道；必要时 dev 模式直连进程内 channel |
| 类 CTP WS 范围膨胀 | 工期失控 | 冻结消息子集清单（见开放问题），多出的进 backlog |
